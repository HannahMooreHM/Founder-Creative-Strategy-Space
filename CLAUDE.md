# CLAUDE.md — Project rules

This repository is Hannah's founder creative-strategy system: five source documents that form one connected method (see `CONTEXT.md` for the architecture and glossary, `DECISIONS.md` for what has been decided and why).

## Rules

1. **Cite before you change.** Any design decision touching the source documents (`master-prompt-v4.md`, `strategy-template-v4.md`, `experiment-engine-build-prompt.md`, `value-prop-validation-engine.md`, `reddit-ai-visibility-engine.md`) must cite the specific sections affected in *each* document and check for cross-document overlap before proposing. Never reason from a summary of a document when the document itself is in the repo.
2. **The constitution binds.** Evidence → interpretation → decision → action (CONTEXT.md). Nothing enters strategy except through the loop or the stamped judgment side-door. New features, sections, or engines must state which door they use.
3. **Vocabulary is canonical.** Use the CONTEXT.md glossary. TWEAK not REVISE/iterate; "validated values" not "proposition values"; `[EVIDENCE]`/`[HYPOTHESIS]` as the only epistemic labels; Segment ≠ ICP.
4. **Current stage: pilots (D7).** Hannah-led service, private kitchen, no founder-facing software. Software-architecture proposals go to the Stage-2 backlog, not into the documents.
5. **British English. Plain words.** Every explanatory sentence must pass the documents' own 15-year-old test. Analogies deepen understanding — use them.
6. **Decisions change deliberately.** To amend a decision, update `DECISIONS.md` with the new reasoning — never let documents drift out of line with it silently.
